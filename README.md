# dwell

> **dwell** — 住下来。也是 *dwell on something*：老想着一件事，萦绕不去。

这是 [xinwithyu/dwell-on-something](https://github.com/xinwithyu/dwell-on-something) 的 Android 封装。

上游是一套**只有前端**的东西：20 篇功能文档，加一个单文件界面 `web/index.html`。
后端它没有开源，只给了实现思路。

这个仓库做的事只有一件：

> **把那套前端装进 APK，并接上一个真能用的模型后端。**

---

## 怎么做的

新增了一个适配层 `app/www/adapter.js`。它接管前端的 `fetch`，
实现前端要的那套 `api/…` 契约，把请求转发到你自己的模型 API。

上游的 `web/index.html` 里本来就有一段**演示模式 IIFE**——它拦下所有 fetch、
喂一份写死的假数据，并在注释里写明：

> 接自己的后端时把这一整块删掉即可，其余代码不用动。

我们就是照这个口子来的：把那段演示换成本适配层，**前端源码其余部分一个字节没动**。

## 支持的协议

装好后在 **右上角菜单 → 设置 → 模型接入** 里配：

| 协议 | 能接什么 |
|---|---|
| **OpenAI 兼容** | OpenAI 官方，以及绝大多数中转站：OpenRouter、DeepSeek、Kimi（月之暗面）、智谱、硅基流动、OneAPI / NewAPI 等 |
| **Anthropic Messages** | Anthropic 官方直连（自动带浏览器直连头） |
| **Google Gemini** | Google AI Studio |

填地址、令牌、模型名，点「试一试」当场验通不通，再保存。
令牌只存在设备本地，不上传任何服务器。

## 已实现的范围

**完整可用：** 聊天主链路（流式输出、思维链、停止、重开一轮）、多会话、
搜索历史、模型与参数配置、上下文用量估算、夜间模式。
以及一个跨域兜底：官方 API 走真 SSE 流式；
碰到不发 CORS 头的自建中转站，自动改走原生 HTTP 通道拿全文再切片（打字机变成假的，但聊得了）。

**留了空壳：** 心跳、日记、待办、日历、共读、健康、仓库、日报、悄悄话这些页面
**界面在、能打开，内容为空**——它们原本依赖上游那套没开源的后端。适配层返回空结构，不报错。

## 构建

```bash
cd app
npm install
npx cap sync android
cd android && ./gradlew assembleRelease
```

产物：`app/android/app/build/outputs/apk/release/app-release.apk`

跑端到端测试（三种协议各打一遍 mock 服务器，55 项断言）：

```bash
npm install && npm test
```

### 签名

`keystore/dwell.jks` **是提交进仓库的**，口令 `dwellon2026`，别名 `dwell`。

这是有意为之：**GitHub 不允许 fork 仓库的 workflow 读 repository secrets**
（防止别人通过改 fork 的 workflow 把密钥偷走），CI 里没法从 Secrets 取，只能把文件放仓库里。

那是一把**自签名的个人证书**，只用来保证你自己的版本之间能覆盖升级。
它不是上架应用商店用的密钥——谁拿到都能签一个同包名的包，
所以别把这个仓库的 APK 和正式上架的版本混着发。

要换自己的密钥：改 `app/android/app/build.gradle` 的 `signingConfigs.dwell`，
或设 `DWELL_KEYSTORE` / `DWELL_PASS` / `DWELL_ALIAS` 环境变量覆盖。

### 发版

```bash
git tag v0.1.1 && git push origin v0.1.1
```

打 tag 触发 GitHub Actions，构建完自动发 Release 并附上 APK。
